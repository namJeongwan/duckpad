# D2 preview

The optional [`com.duckpad.d2` native plugin](https://github.com/namJeongwan/duckpad-plugin-d2)
is distributed separately from Duckpad. Version **0.1.0** requires Duckpad
**0.18.0** (host API **1.6.0**) and macOS 13+. Duckpad 0.17.0 exposes API 1.5.0
and cannot load it. The native C ABI remains v1.

Install **D2** from **Plugins Admin → Available Plugins**, or download the
[0.1.0 release ZIP](https://github.com/namJeongwan/duckpad-plugin-d2/releases/tag/v0.1.0),
extract it and select the `.duckpad-plugin` folder with **Install Plugin**.

Open a `.d2` document and run **Plugins → D2**. **Preview** reads the current
editor buffer, including unsaved edits; **Open file…** reads a chosen UTF-8 file.
The dock supports fit-width, zoom, scrolling, a separate larger preview window,
and PNG/SVG export. **Ctrl+W** closes the dock while preserving the editor.
Rendering is explicit; typing does not continuously launch the CLI.

In **Settings**, **Set up automatically** downloads pinned official D2 **0.9.0**
for the running architecture, verifies archive and binary SHA-256, and stores it
in the helper's private cache together with upstream license notices. This is
an explicit network operation; diagrams are never uploaded. After setup, renders
work offline. Alternatively enter a compatible D2 Mach-O executable path, or
leave it blank to discover the managed runtime, `/opt/homebrew/bin/d2`, then
`/usr/local/bin/d2`. A custom runtime is user-selected trusted native code;
its bytes are not verified against the pinned managed-runtime checksum.

Each render uses the authenticated helper without administrator privileges and
a private temporary job. D2 runs with network denied, writes limited to the
job and data reads limited to the job, executable and system resources. External
imports and local/remote images outside that job are unsupported. Source is
passed on stdin and temporary source/output files are removed after the job.
Settings store only the executable path. Native plugin authorization still
permits trusted code in the host process.

The first version renders the root board using the bundled Dagre layout and
light/dark themes. Alternate layouts, external resources and multi-board export
are unsupported. Source is limited to 512 KiB, process time to 90 seconds and
SVG/output to 32 MiB. PNG snapshots are bounded to 8192 pixels per axis and
16 million pixels; very extreme aspect ratios report an error. SVG export
retains vector content. Setup and render errors appear in the panel. Closing
cancels that connection's work; stale results cannot restore a closed preview.
All eight Duckpad UI languages are included.

## Build and test

From the standalone plugin checkout, pointing to this matching host checkout:

```sh
bash scripts/build.sh native /path/to/duckpad
# For a distribution candidate, compile both architectures:
bash scripts/build.sh universal /path/to/duckpad
# Requires the already-configured publisher key outside the repository:
swift scripts/sign.swift dist/com.duckpad.d2.duckpad-plugin
swift scripts/verify.swift dist/com.duckpad.d2.duckpad-plugin
```

Install the signed `.duckpad-plugin` folder through **Plugins Admin → Install
Plugin** in a compatible app. Distribution and local builds use ad-hoc Mach-O signing
and publisher package signatures, without Apple notarization.
See [shared preview verification](../../SDK/DiagramPreview/overview.md).

## Editor support

The main editor recognizes `.d2` and offers D2 in the Language menu without the
plugin. Structural highlighting covers strings, comments, block labels, arrows,
numbers, keywords and common properties using the current editor palette.
It is not a validating parser, language server or folding implementation.

Upstream: [D2 source and releases](https://github.com/d2lang/d2),
[D2 introduction](https://d2lang.com/tour/intro/).
