# List services and Clipboard History

The app repository owns host APIs and native presentation. Plugin source lives in `namJeongwan/duckpad-plugin-clipboard-history`; installable release metadata belongs to `namJeongwan/duckpad-plugins`. Repositories and version numbers are independent. The catalog records published immutable release assets.

Duckpad 0.6.0 exposes host API 1.3.0. Released Duckpad 0.5.0 supports API 1.0.0 and cannot run the new service plugin. The plugin declares this compatibility range in its signed manifest.

## Host boundary

A command with `inputScope: service` uses the existing zero-import WASM ABI and bounded XPC/development transport. Its input and output are opaque values; the runtime returns `serviceOutput` and never editor edits. Commands with `selection` or `document` scopes retain their previous behavior. A service needs `storage.plugin` and `ui.list`; clipboard observation and selection effects additionally require declared `clipboard.read` and `clipboard.write` capabilities. These capabilities have application scope and are authorized when the verified package is installed or enabled.

The host provides one application-owned coordinator, weak window authority registrations, publisher/plugin-isolated storage, and a native searchable sidebar docked to the editor’s right edge. Policy generations prevent a stale window's grants from reviving a revoked service. When one window closes, a remaining authorized window can own the existing session. Opening another window never creates a second clipboard observer or a competing state writer. Closing all owner windows stops collection.

Clipboard monitoring polls only while an authorized observer exists. The first observation starts after enabling; pre-existing clipboard contents are not imported. Concealed, transient, and autogenerated pasteboard markers are excluded. This version observes text only. Clipboard contents, state, and query strings do not appear in logs. One background event and the latest query are coalesced while explicit actions remain ordered.

Service state is stored as private opaque bytes below `Duckpad/PluginData/<plugin-id>/<publisher-fingerprint>/<command-id-sha256>/state.bin`. Each service command has independent serialized state, preventing sibling commands from overwriting one another. Atomic writes use mode 0600; directories use 0700. Symlink state files are rejected. Service inputs cap state at 512 KiB, event payload at 256 KiB, and query at 16 KiB so a full state can still accept a new event within the existing runtime input limit. The plugin itself enforces its 200-entry and 512 KiB budgets, evicting oldest unpinned entries. Oversized items never evict existing history.

The sidebar stays open after paste and while changing tabs; its divider can be dragged to resize it. Opening the dock temporarily increases the window’s minimum width, and closing it restores the previous minimum. Return activates a row only while the list or search has focus, so editor newlines remain normal. Selection results are bound to the sidebar presentation that requested them. Closing/reopening the panel or selecting the command in another window invalidates pending effects. Each selection captures the current document, rather than retaining the document that opened the sidebar. Paste rechecks that target document context plus native editor identity and the complete serialized selection, including multiple carets and virtual spaces and uses the existing native paste path, preserving normal Undo and recovery behavior.

Enabled, authorized service commands appear in **Tools**, with their declared shortcut shown by the native menu. Clipboard History opens with **Tools → Clipboard History** or **⌥⌘V**. Disabling the plugin or removing its required grants removes this entry. Selection/document transformation commands remain in **Plugins**.

## Installation and development

Build the separate plugin with `cargo test` and `bash scripts/build.sh`. Its `scripts/sign.swift` reuses the persistent Clipboard publisher key outside the repository, with an optional explicit key path. Clipboard uses `clipboard-release-1`; the original bundled text-tools key is unchanged. The app and catalog contain only the corresponding public key. The signing command does not generate or rotate keys. Never commit a private key. The app verifies the signed inventory and module before installation, copies into private staging, revalidates the exact digest, and publishes a new version without replacing an existing version. Use **Plugins → Manage Extensions… → Install Plugin…**. Installation enables the plugin with its declared capabilities; no separate Grant action is required.

The first release uses local signed package installation and network updates. Catalog browsing/first-install UI, image history, global hotkeys, and pasting into other applications are not included in this change.

## Verification

- Plugin Rust tests cover deduplication, Unicode, exact paste content, pins, deletes, clear, restart state, byte/count eviction, oversized captures, malformed inputs, and all-pinned capacity.
- App service tests prove no document capture/edits, grant checks, revocation, and rejection of document-edit responses.
- Native list tests cover surviving windows, stale policy generations, and delayed selection after panel close/reopen.
- `DUCKPAD_CLIPBOARD_PLUGIN_MODULE=/path/to/module.wasm swift test --no-parallel --filter ExtensionServiceIntegrationTests` executes the separately built guest in the actual WAMR runtime and verifies private storage and value framing. Without the environment variable, the separate-guest check reports an explicit skip.
- Catalog validation is dependency-free Python and rejects malformed identities, duplicate keys/releases, unknown signing keys, mutable download URLs, path traversal, and incompatible API ranges.

## Retention and sequential paste

The list value protocol v2 sends a host Unix timestamp after the query and returns a retention-days field after selected text. Choices are 1 day, 3 days, and 1 week (default). The plugin expires all old entries, including pins, before each event, and the host queries every minute while active to persist cleanup even if the dock is hidden. On reopening, expiration precedes selection; closed/disabled apps cannot clean disk until reactivated. Unexpired history survives restarts. Legacy records without timestamps start their age once at migration. Reducing the period immediately deletes old records.

Paste Next inserts the currently selected filtered row then selects the following one. It stops at the last row; selecting another row or changing search starts again. The normal Paste action and Return keep their existing behavior. Pending insertions disable action controls and advance only after target validation succeeds. The host excludes its own pasteboard writes from capture to keep sequence order stable.

The dock displays full selected text in a read-only, selectable preview below the list. It uses a separate `preview` event, with no paste side effects. Pending previews are coalesced and checked against the current row, query, and dock presentation; closed or changed selections cannot show stale content. Labels are centered inside reusable native table cells. Regression tests capture light/dark appearances and verify text frame centering as well as exact multiline preview content.

The host supplies Clipboard labels in all eight app languages. Deleting the selected entry keeps the nearest surviving next entry selected, or the previous entry at the end, and preserves the list scroll position.
