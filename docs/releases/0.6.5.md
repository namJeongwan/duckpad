# Duckpad 0.6.5

- Fix long pauses when typing near the end of large text files. macOS input-method and accessibility range queries use Scintilla's maintained UTF-16 line index instead of rescanning the preceding document. Korean composition, Unicode selections, and Undo/Redo retain their behavior.
- Show a bounded, read-only text preview before the complete file is read and verified. Load the editor in chunks with progress; enable editing when loading finishes. Failed or cancelled previews preserve existing documents and recovery data.
- Reduce repeated full-document work during tab switching and closing. Recovery uses private APFS clones and patches changed regions while preserving independent, durable generations and complete integrity checks. Other filesystems retain the full-write fallback.
- Prepare the website's version and download data for 0.6.5. Live Pages builds resolve published release assets so an unpublished version does not create broken download links.

App and helpers: **0.6.5 (43)**. Requires **macOS 13 or later**.

## Installation and release status

This PR prepares 0.6.5; release assets have not been published. Once available, download `Duckpad-0.6.5-universal.dmg`, open it, and drag Duckpad into Applications. The ZIP alternative is `Duckpad-0.6.5-universal.zip`; verify it against `SHA256SUMS.txt`.

Local validation uses an ad-hoc-signed Apple Silicon build, not an Apple-notarized release. Universal packaging and execution on physical Intel/macOS 13 hardware remain release-time checks.

## Validation and limitations

Input-index and progressive-loading regression suites passed 11 tests, followed by 49 native bridge tests. Earlier targeted storage, recovery, and file-operation suites passed 85 tests. Coverage includes Korean composition, non-BMP characters, CRLF, partial-surrogate ranges, shared views, binary-to-text replacement, cancellation, exact saved bytes, recovery corruption, and immutable checkpoints.

On one 1.50 GB / 52.34-million-line local copy, the first preview appeared in 16.78 ms. Thirty-two EOF input-manager query pairs took 0.167 ms; input/recovery bursts had a maximum 25.08 ms main-thread heartbeat gap. Dirty tab closure took 0.16 s. Saved hashes and final unsaved recovery matched.

Complete loading took **13.33 seconds**, slower than the preceding preview because the UTF-16 index must be maintained. The index also uses additional memory. An exceptionally long single physical line still requires scanning that line. Full-file storage/copy costs remain; saves measured 0.90–2.03 seconds in this run. These are individual measurements, not latency guarantees. EOF surrounding-text queries in the large probe are empty ranges; nonempty Unicode queries are tested separately.

The 0.6.5 (43) native validation package passed verification of the app and both helper versions. Package smoke checks covered Finder opening, bookmark save/relaunch, window layout, and sandboxed XPC isolation. Native Save panel UI automation was skipped. The website checks all eight language dictionaries and 32 routes; this change adds no translated copy.

See [performance details](../large-file-performance.md) for the measurements and their scope. After publishing verified 0.6.5 assets, run the Website workflow on `main` to update Pages.
