# Duckpad 0.18.3

Find/Replace in Files keeps results and their preview visible while a new query
is being typed and searched. Previously, each edit cleared both views twice,
causing a blank flash. Old results cannot activate or replace anything while the
next query is pending. Empty final results and errors clear the view, and late
preview responses cannot restore results after a failure. Repeated or growing
progress preserves the selected match and preview text selection.

Multi-root searches share the remaining file-count and input-byte budgets across
roots that have not started. A large earlier project can no longer consume the
whole 10,000-file/256-MiB allowance before later projects are visited. This fixes
missing later-root matches such as `hongyoung` in a configuration URL. Unused
capacity carries forward; earlier roots can remain partial even if later roots
leave spare capacity. Truncation stays visible and disables Replace All. Global
file, byte, match and result-memory bounds remain in force.

When **Share usage statistics** is enabled, bounded background batches can also
use metered and Low Data Mode connections. Previously, those network restrictions
could produce an offline error even while the collection API was reachable.
Turning sharing off still cancels delivery and clears queued counters. Existing
timeouts, batch/request limits, ephemeral sessions and redirect rejection remain.
The statistics service's database memory limits were repaired separately. Earlier
missing events may remain absent; the fix does not fabricate historical activity.

## Compatibility and installation

The app and all three helpers are **0.18.3 (74)**, upgrading **0.18.2 (73)**.
Requires macOS 13 or later; the universal app includes Apple Silicon and Intel.
Host API **1.6.0**, native ABI v1 and independently released plugins are unchanged.
No runtime dependencies were added or upgraded.

Download `Duckpad-0.18.3-universal.dmg` or `Duckpad-0.18.3-universal.zip` and verify
against `SHA256SUMS.txt`. After the tap update, Homebrew installations can run:

```sh
brew update
brew upgrade --cask --greedy namjeongwan/duckpad/duckpad
```

Existing installations can use **Check for Updates** after the signed feed is
published. Distribution is ad-hoc signed, without Developer ID signing or Apple
notarization.

## Validation and limits

Search validation passed **42 focused test functions**, including five new UI
regressions, file/byte fairness variants, native unsaved-buffer searching, stale
actions, streamed progress, replacement boundaries and simulated Korean input.
Before the fixes, the flicker and both later-root fairness cases fail. Search
scope methods passed in isolated processes; combined-suite completion was not
verified. User documents were not modified by these tests.

An additional **13 statistics tests** passed. The unchanged native transport
reproduced an offline failure on the current restricted connection; the fixed
transport sent a Debug diagnostic through the public endpoint, and its exact
record was verified in ClickHouse. Debug records are separate from Release
usage. The opt-in `scripts/smoke_usage_statistics.swift` repeats this check without
opening user sessions or changing preferences. Live Release-user ingestion and
the authenticated dashboard UI are not claimed as tested by this diagnostic.

Universal bundle, app/helper versions and architectures, packaged resources,
default app smokes, all eight locales and DMG/ZIP integrity are required before
publication. Intel hardware, macOS 13 runtime, physical Korean IME and a full
repository suite are not claimed. Optional native Save-panel automation is
outside this patch's validation.
