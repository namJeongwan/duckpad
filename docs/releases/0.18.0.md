# Duckpad 0.18.0

Duckpad adds optional D2 and standalone Mermaid previews and keeps search matches
comfortably visible in the main text/code editor. The README now lists all eight
bundled and optional plugins, their installation paths and runtime requirements.

## Diagram plugins

Install the separate **0.1.0** packages from **Plugins → Plugins Admin → Available
Plugins**, or download a plugin ZIP, extract it and choose the `.duckpad-plugin`
folder with **Install Plugin**:

- [D2 0.1.0](https://github.com/namJeongwan/duckpad-plugin-d2/releases/tag/v0.1.0)
- [Mermaid 0.1.0](https://github.com/namJeongwan/duckpad-plugin-mermaid/releases/tag/v0.1.0)

Both plugins preview the active unsaved buffer or a selected UTF-8 file in a
native dock, with fit-width, zoom, a larger window and PNG/SVG export. Ctrl+W
closes the dock. They do not edit the source or its Undo history. Source is
rendered locally; rendering is explicit rather than repeated on every keystroke.
Both packages include all eight Duckpad UI languages.

D2 requires Duckpad 0.18.0's **host API 1.6.0**. Its Settings panel can explicitly
download and verify official D2 0.9.0, or use a compatible local executable.
Rendering uses the authenticated helper and a private job with network denied
and file access limited to runtime/system/job resources. The first version uses
Dagre and renders the root board; external imports, images and alternate layouts
are unsupported.

Mermaid embeds the existing pinned Mermaid 12.0.0 runtime in its signed native
module. It needs no external Node.js, CLI or browser download after installation.
WebKit uses a nonpersistent page, strict Mermaid configuration, network-blocking
CSP and SVG cleanup. Existing Mermaid fenced blocks in Markdown remain built in.
The standalone plugin accepts Mermaid source without Markdown fences.

The editor recognizes `.d2`, `.mmd` and `.mermaid` independently of the plugins,
with structural highlighting using its current palette. These lexers do not add
syntax validation or folding.

## Search visibility

Find next/previous, result activation and folder-search activation use a dedicated
reveal operation. It unfolds containing regions, fits horizontal endpoints and
keeps up to three display rows of context above and below the match. Wrapped
lines and small panes use available space; a match larger than the viewport
follows its caret. Already comfortably visible results do not move the viewport,
and only the focused split pane scrolls. This follows Zed's fit/context behavior
without importing Zed source. Typing and completion scrolling retain their
existing behavior.

## Compatibility and installation

The app and all three helpers are **0.18.0 (71)**, upgrading **0.17.0 (70)**.
Requires macOS 13 or later; universal app and plugin packages include Apple Silicon
and Intel. The native C ABI remains v1; host API advances to 1.6.0. Existing
language support packages remain compatible. D2 and Mermaid are not bundled into
the app and keep their independent 0.1.0 versions.

Download `Duckpad-0.18.0-universal.dmg` or `Duckpad-0.18.0-universal.zip` and verify
against `SHA256SUMS.txt`. After the tap update, Homebrew installations can run:

```sh
brew update
brew upgrade --cask namjeongwan/duckpad/duckpad
```

Check for Updates becomes available after the signed Sparkle feed is published.
App and plugin Mach-O files use ad-hoc signatures; plugin inventories also carry
publisher signatures. This release is not Developer ID signed or Apple notarized.

## Validation and limits

29 focused Swift test functions passed during implementation: 20 runtime,
syntax/detection and viewport tests, plus nine package/activation/installation
checks. Actual D2 setup/checksums/cache reuse, Korean rendering and denied
external imports were exercised with a successful unsandboxed control. Tests also
covered WebKit PNG pixels and SVG cleanup, Mermaid flowchart/sequence/class
rendering, errors, cancellation, stale replies/exports, native ABI loading, all
eight locale resources and narrow 300/560-point translated controls.

The development app passed bundle/signature verification, default isolated app
smokes and sandboxed D2 XPC-to-WebKit plus embedded Mermaid rendering checks.
Release artifacts are rebuilt from merged main and verified before publication.
Optional native Save-panel automation was skipped. Two broader search presentation
tests also fail on the unchanged baseline (`incrementalFindDoesNotExpandTheResultsList`
and `routedFolderSearchOpensIdentityCheckedResultAndSelectsUTF8Range`); the ten
native viewport regressions pass.

Diagram input is limited to 512 KiB, output to 32 MiB, and PNG snapshots to 8192
pixels per axis and 16 million pixels. D2 rendering has a 90-second process limit;
Mermaid rendering has a 30-second limit and 5000-edge bound. Extreme aspect ratios
report an error. Native plugin installation remains a code-trust authorization,
not isolation for arbitrary native code.

Intel hardware execution, macOS 13 runtime and every Mermaid diagram family were
not individually tested. See [D2](../plugins/d2.md), [Mermaid](../plugins/mermaid.md)
and [verification details](../../SDK/DiagramPreview/overview.md).
